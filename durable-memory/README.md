# Gallery maintenance

- `catalog.json` is the 17-host inventory. Its host previews are exact copies of upstream `docs/images/` files, with SHA-256, producing script, attribution, and source commit where available. Read sibling repositories only; never edit them from this project.
- `showcases.json` lists the compositions (25 as of this note: 01-15 the original set, 16-25 the Kepler, oscillator, rigid-body, FEM, heat, forecast, decomposition, regression, date-axis and queue batch). The CI autorun matrix must list every number; a composition missing from the matrix is never executed in CI. Each `.lms` binds two or three released hosts with `cli`/`install`, writes its own input data, executes its bytecode, and writes an `images/showcase-NN-*.png` (or `.gif` for the animated one, which also needs `ffmpeg`). Nothing depends on the checkout working directory. Compositions that combine a drawing with a plot place the lmdraw PNG inside the lmplot figure with gnuplot's `set pixmap`.
- Update composition previews with `examples/render-all.sh`. This runs every program in a separate fresh temporary directory and retains execution logs. Use `--only 04` to regenerate one example.
- Regenerate README, attribution and the example index with `python3 scripts/build-readme.py`. CI rejects stale generated documents.
- `./test.sh` validates PNG/GIF signatures, CRCs, decoded size, preview size budgets, SHA-256 attribution, cross-host bindings, autorun captions and local links; it requires at least 14 compositions. `--network` also checks published HTTP links; planned upstream repository links are reported as skips, not advertised as verified. Remove the planned status once those repositories are public.
- `./test.sh --urls` is the publication acceptance check: it invokes every public raw URL with `lmctl autorun` from an empty directory. The runner reports retained `results.json` files and per-example logs outside the checkout.
- Writing a composition (lessons from the 15 here): inside a `_dsl_` block only the host schema plus `float, str, sin, cos, sqrt, abs, floor, pow, min, max, clamp, lerp, ease, int` exist (no `split`, `exp`, `log10`), and outer lmscript variables are invisible unless interpolated with `${name}`. `${}` prints a whole-number float as an integer literal, so perturb such values (`+ 0.001`) or write them as DSL literals; `float()` only widens ints. Host output lines are read back from `r.stdout` (the host appends a `{"ok"...}` line; cut it with `split(r.stdout, "{\"ok\"")[0]`). lmdraw only writes PNGs under `build/rendered/`; lmplot takes inline data through `plot.data("NAME", text)` then `$NAME`, not `'-'`. Use `@latest` only against the published release API (the local checkouts may be ahead).
- Output formats differ by host, and each composition has to read its own: `lmnum` `save_csv` writes space-separated rows with no header; `lmspace` writes comma-separated rows with no header; `lmphysics` `save_csv` writes a header whose column names are `body.column`; `lmfluid` `sample(...).save_csv` writes `x,y,0,value`. A gnuplot `set datafile separator ','` applies to the whole plot, so set it only for comma files.
- Inside `_dsl_` there is no ternary operator, no `assert` (use `num.assert_close`, `fluid.assert_true` or a host check), and no `exp`; use `pow(2.718281828459045, x)`. Top-level lmscript has `split`, `lines`, `join`, `csv_parse`, `write_file` but no `float` or trigonometry.
- lmplot needs `plot.png(...)` before `set multiplot`; otherwise the terminal change is refused at run time.
- Scripts are MIT. Host binaries run as separate processes and are not redistributed. Retain the upstream attribution and license notice when refreshing copied artwork.
